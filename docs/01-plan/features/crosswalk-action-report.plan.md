# Plan: 횡단보도 설문결과 + 동대문경찰서 면담 결과 주민 보고 페이지

## Executive Summary

| 항목 | 내용 |
|------|------|
| Feature | crosswalk-action-report (횡단보도 활동 결과 보고) |
| 시작일 | 2026-05-13 |
| 목표일 | 2026-05-17 |
| 예상 기간 | 4일 |
| 페이지 경로 | `/crosswalk-action` (또는 `/crosswalk-report`) |
| 대상 | 이문동 주민(설문 참여자 + 미참여 주민) |

### Value Delivered

| 관점 | 설명 |
|------|------|
| **Problem** | 25건의 횡단보도 설문이 수집되고 동대문경찰서 면담까지 진행됐으나, 주민들은 "내가 낸 의견이 어떻게 됐는지" 알 길이 없다. 기존 `/survey-results` 페이지는 전문가 분석 중심으로 분량이 길고 주민 알림용이 아니다. |
| **Solution** | "주민이 모은 의견 → 후보가 전달 → 경찰서 답변"의 3단계 스토리를 한 페이지로 압축. 면담 사진을 신뢰 근거로 제시하고, 핵심 4대 이슈(대각선 횡단보도·신호시간·비보호 좌회전·횡단보도 사각지대) 각각에 대해 "주민 요구 → 경찰서 답변 → 다음 단계"를 카드로 정리한다. |
| **Function UX Effect** | 주민이 SNS·카톡 링크로 들어와 **스크롤 3번**으로 "내 의견이 진짜 전달됐고, 이런 답변을 받았고, 다음 단계는 이거구나"를 파악할 수 있다. 면담 사진으로 "말로만이 아니라 실제로 만났다"는 증거를 제시한다. |
| **Core Value** | "데이터로 신뢰를(Trust through data)" — 감정 호소가 아니라 설문 수치 + 면담 사진 + 답변 인용으로 후보의 실행력을 증명한다. "주민과 함께 일해온 사람"이라는 슬로건을 한 페이지의 스토리로 체현. |

## 1. 배경 및 목적

### 1.1 현재 상태

**기존 자산**
- `/crosswalk-survey` (`src/app/crosswalk-survey/page.tsx`): 설문 입력 페이지, 현재 운영 중 (`SURVEY_CLOSED = false`)
- `/survey-results` (`src/app/survey-results/page.tsx`): 전문가 분석 포함 결과 페이지 (약 900줄, 매우 상세)
- `crosswalk_police_reply.md`: 빈 파일 (면담 답변 내용 입력 대기)
- `photo_2026-05-13 23.28.41.jpeg`: 동대문경찰서 면담 사진 (후보가 자료를 보여주며 설명하는 장면, 1장)
- Supabase `survey_responses` 테이블: 25건 응답 적재
- 핵심 분석 결과: 대각선 횡단보도(14건), 신호시간(8건), 비보호좌회전(4건), 횡단보도 사각지대(5건)

### 1.2 문제점

1. **결과 확산 채널 부재**: 설문 참여자에게 "전달했다 → 답변 받았다"는 후속 보고가 닿지 않음
2. **기존 결과 페이지는 알림용이 아님**: `/survey-results`는 전문가 소견·교차분석 등 분량이 많아 일반 주민이 모바일에서 끝까지 읽기 어려움
3. **면담 증거 미공개**: 동대문경찰서 면담 사진이 사이트 어디에도 노출되지 않음 — 후보의 핵심 실행 증거가 사장됨
4. **다음 단계 불명확**: 주민 입장에서 "이제 어떻게 되는 건가?"에 대한 답이 없음
5. **재공유 동기 부재**: 한 페이지로 압축돼 카톡·SNS로 공유할 만한 컨텐츠가 없음

### 1.3 목표

- 모바일 기준 **스크롤 3~5회 안에 완독 가능**한 한 페이지 알림 문서 제작
- "수집(25건) → 전달(면담 사진) → 답변 → 다음 단계" 4단 스토리 구조
- 기존 `/survey-results` 페이지는 "더 자세히 보기" 링크로 보존 (전문 분석은 그대로)
- 카톡·SNS 공유 시 OG 이미지 + 핵심 메시지 노출 가능하도록 메타데이터 작성
- 면담 답변 내용은 **사용자(후보)가 입력 예정** — 페이지는 비어도 빌드/배포 가능한 placeholder 구조 제공

## 2. 기능 정의

### 2.1 F1: 히어로 - 활동 결과 요약 (우선순위: P0)

**목표**: 첫 화면에서 "무엇을 했는가"를 5초 안에 전달

- 라벨: "주민 의견 → 동대문경찰서 전달 완료"
- 제목: "여러분의 25건이 경찰서로 전달됐습니다"
- 부제: "주민 설문 결과를 바탕으로 동대문경찰서를 직접 찾아 면담했습니다"
- 핵심 수치 3개 카드:
  - 25건 (수집된 의견)
  - 4대 (전달한 핵심 문제)
  - 1회 (경찰서 면담 - 추후 확장 가능)
- 배경: 기존 디자인 시스템 유지 (`bg-gradient-to-br from-sky-200 via-sky-300 to-sky-400`)

### 2.2 F2: 면담 사진 + 캡션 (우선순위: P0)

**목표**: "말로만이 아니라 실제로 만났다"는 신뢰 근거 제시

- `photo_2026-05-13 23.28.41.jpeg` 풀와이드 표시 (모바일 최적화)
- 사진 캡션: "2026년 5월 13일, 동대문경찰서에서 횡단보도 개선 면담 진행"
- 사진 출처: `src/app/crosswalk-survey/`에 있으나 `public/` 으로 이동 필요 (Next.js 정적 자산)
- 추후 다른 면담 사진이 추가될 수 있도록 배열 기반 구조로 설계

### 2.3 F3: 주민 의견 요약 - 4대 이슈 (우선순위: P0)

**목표**: 25건이 어떤 의견이었는지 한눈에 보이는 압축 요약

`/survey-results`의 4대 핵심 문제를 카드 형태로 압축:

| 순위 | 이슈 | 언급 건수 |
|------|------|-----------|
| 1 | 대각선 횡단보도 필요 | 14건 이상 |
| 2 | 보행 신호 시간 부족 | 8건 이상 |
| 3 | 비보호 좌회전 위험 | 4건 |
| 4 | 횡단보도 사각지대(빽다방 앞 등) | 5건 |

각 카드:
- 아이콘 (Lucide React - 기존 페이지와 일관성)
- 이슈 제목
- 언급 건수 뱃지
- 주민 원문 1줄 인용 (가장 인상적인 것)
- "자세히 보기" → `/survey-results` 해당 섹션 앵커 링크

### 2.4 F4: 동대문경찰서 답변 - 4대 이슈별 (우선순위: P0)

**목표**: 면담에서 받은 답변을 이슈별로 정리

각 이슈 카드 옆/아래에 답변 영역:
- 답변자: "동대문경찰서 교통과 ○○○ 답변"
- 답변 내용 (3~5줄)
- 처리 상태 뱃지:
  - 🟢 "긍정 검토" / 🟡 "추가 협의 필요" / 🔴 "관할 외(구청 이관)" / ⏳ "현장 점검 예정"
- 후속 일정 (있으면): "2026-06-XX 현장 점검 예정"

**⚠️ 데이터 입력 대기**: 실제 답변 내용은 후보(사용자)가 `crosswalk_police_reply.md` 또는 별도 데이터 파일에 작성 예정. 페이지는 빈 답변이어도 깨지지 않게 fallback UI 제공 ("답변 정리 중입니다").

### 2.5 F5: 다음 단계 - 후보의 약속 (우선순위: P1)

**목표**: "이제 어떻게 되는가"에 대한 답 제공

타임라인 형식:
- ✅ 2026-04~05: 주민 설문 수집 (25건)
- ✅ 2026-05-13: 동대문경찰서 면담
- 🔄 진행 중: 동대문구청 교통행정과 추가 면담 (있다면)
- ⏳ 계획: 서울시 교통 안전 특별관리구역 지정 요청
- ⏳ 계획: 주민 결과 보고 간담회 개최

### 2.6 F6: CTA - 추가 의견 받기 / 공유하기 (우선순위: P1)

**목표**: 페이지 이탈을 참여로 전환

- 카드 1: "아직 의견을 못 주셨다면" → `/crosswalk-survey` 링크 (설문 진행 중일 때만)
- 카드 2: "이웃에게 알려주세요" → 카카오톡/링크 공유 버튼
- 카드 3: "전체 분석 보기" → `/survey-results` 링크

### 2.7 F7: SEO/OG 메타데이터 (우선순위: P1)

**목표**: 카톡·SNS 공유 시 미리보기 최적화

- `<title>`: "이문동 횡단보도 25건 의견, 동대문경찰서 전달 완료 — 오준석"
- `<meta description>`: "주민 25명이 모은 횡단보도 개선 의견을 동대문경찰서에 직접 전달했습니다."
- OG image: 면담 사진 또는 별도 디자인 카드 (1200x630)
- Twitter Card: summary_large_image

## 3. 비기능 요구사항

### 3.1 성능
- 첫 콘텐츠 페인트 1.5초 이내 (모바일 3G 기준)
- 면담 사진은 `next/image`로 최적화 (WebP 자동 변환, lazy load는 fold 아래만)

### 3.2 접근성
- 본문 16px 이상 (어르신 가독성)
- 색상 대비 WCAG AA 이상
- 사진에 의미 있는 alt 텍스트 ("동대문경찰서 면담 장면 - 오준석 후보가 주민 설문 결과를 설명하는 모습")

### 3.3 반응형
- 모바일 우선 설계 (375px 기준)
- 태블릿/데스크톱은 max-w-3xl 중앙 정렬 (기존 페이지와 일관성)

### 3.4 유지보수성
- 답변 내용은 컴포넌트가 아닌 **데이터 파일**로 분리 (`src/data/crosswalk-police-response.ts`)
- 향후 다른 면담(구청 등) 추가 시 같은 페이지에 섹션 추가 가능한 구조

## 6. 리스크 / 미정 사항

### 6.1 ⚠️ 리스크: 면담 답변 콘텐츠 부재
- `crosswalk_police_reply.md`가 비어있음
- **대응**: Design 단계에서 사용자에게 답변 내용 요청. 입력 전에도 페이지는 "답변 정리 중입니다" placeholder로 빌드/배포 가능하도록 구조화

### 6.2 ⚠️ 리스크: 사진이 1장뿐
- 단일 사진으로 시각적 임팩트가 약할 수 있음
- **대응**: 사진은 풀와이드 + 캡션 강조로 처리. 향후 추가 사진 들어올 수 있는 갤러리 구조 설계

### 6.3 ❓ 미정 사항
1. **페이지 경로명**: `/crosswalk-action` vs `/crosswalk-report` vs `/crosswalk-update` — Design 단계에서 결정
2. **Navbar 노출 여부**: 위 4.2 옵션 A/B/C 중 선택
3. **답변자 실명 공개 여부**: 면담 상대방 이름·직책을 공개해도 되는지 후보 확인 필요
4. **공약 연계**: "이걸 위해 이런 공약을 했다" 식 공약 카드 연결 여부

### 6.4 의존성
- 면담 답변 데이터 입력 (후보 → Do 단계 전까지)
- 사진 추가 (선택 사항, 있으면 더 풍성)

## 7. 성공 기준

### 7.1 정량 지표
- 모바일 페이지 로딩 시간 < 2초
- 페이지 길이 < 3000px (스크롤 3~5회)
- Lighthouse Performance 90+, Accessibility 95+

### 7.2 정성 지표
- "내 의견이 전달됐다는 게 보인다" — 설문 참여 주민 피드백
- 카톡·SNS 공유 시 미리보기에 핵심 메시지 노출
- 기존 `/survey-results` 페이지의 가치를 훼손하지 않음 (전문 분석 보존)

### 7.3 Anti-Goal (하지 않을 것)
- ❌ 기존 `/survey-results` 페이지 대체 (그건 그대로 둠)
- ❌ 새로운 설문 기능 추가 (이 페이지는 알림 전용)
- ❌ 정치적 공약·비전 나열 (이 페이지는 "한 가지 사안의 진행 결과"만 다룸)
- ❌ AI 생성 템플릿 느낌 (3-column 카드 그리드 남발 금지, 보라색 그라데이션 금지)
